# Open Documentation and Architecture Issues

This file records audit findings that are not current implementation Debt and
cannot safely be resolved inside DOC-002. Live capability Debt remains generated
from programme state in [`docs/current/DEBT.md`](../current/DEBT.md).

## DOC-ISSUE-001 Generated index cannot include the numbered layer

- **Status:** open
- **Finding:** `docs/DOCUMENT_INDEX.md` is generated by a script that lists the
  retained product/architecture/programme classes but not `00` through `08`.
- **Why not changed:** DOC-002 forbids script and configuration changes; manual
  edits would be overwritten.
- **Impact:** humans and agents must use `docs/README.md` for the numbered domain
  map and the generated index for programme governance.
- **Closure:** a future docs-tooling Work Order updates generator/tests and
  proves idempotent sync without changing authority semantics.

## DOC-ISSUE-002 “Latest Evidence” means latest programme Evidence

- **Status:** open
- **Finding:** generated current documents label the programme state's
  `latest_evidence_id` as “Latest evidence”, while newer independent DOC
  Evidence can exist.
- **Impact:** readers may mistake the field for newest repository-wide Evidence.
- **Closure:** change the generator label to “Latest programme Evidence” under a
  docs-tooling Work Order; never hand-edit generated output.

## DOC-ISSUE-003 Legacy Markdown navigation

- **Status:** partially addressed
- **Finding:** several programme work-package and editing specification files
  place multiple `##` headings on one physical line, reducing rendered
  navigation quality though not changing semantics.
- **Closure:** reformat Markdown only, verify zero content/authority change, and
  retain programme fingerprints when governed checks treat docs as code input.

## DOC-ISSUE-004 Future object contracts are not implementation

- **Status:** open by design
- **Finding:** Creator Model, expanded Evidence Graph relations, creative
  knowledge, learning events, AI-enhanced/generated provenance, and autonomy
  policy are specified views without promoted schemas or runtime support.
- **Impact:** future agents could treat document existence as capability.
- **Closure:** one governed Work Order per bounded contract with schema,
  Project Host ownership, failure closure, persistence/reopen, privacy, tests,
  Evidence, and required human review.

## DOC-ISSUE-005 Historical root blueprint remains outside the domain map

- **Status:** retained compatibility
- **Finding:** `AI Vlog Co-Editor 工程架构与仓库蓝图.md` is a historical source
  at repository root.
- **Impact:** it can be mistaken for current architecture if opened directly.
- **Closure:** keep it clearly labeled historical in root navigation; do not
  infer current requirements from it or move it without a link-migration Work
  Order.

## DOC-ISSUE-006 Work Order and ADR lifecycle metadata drift

- **Status:** open
- **Finding:** documentation-expansion candidate Work Orders do not all include
  the lifecycle header required by their own specification; older ADR records
  do not all contain every section now required by the ADR policy.
- **Impact:** a candidate Work Order can be mistaken for ready work, and an old
  decision may be harder to audit under the current template.
- **Closure:** a focused governance-maintenance task adds explicit lifecycle
  metadata and missing non-semantic ADR sections without changing decisions or
  activating packages.
