# ADR-0060：复用 Hypit 组件与受控图形执行适配

日期：2026-11-11。状态：**Proposed（研究形成的实施建议，未安装、未实施、未验收）**。

本文属于稳定架构决策层，由 [决策索引](README.md) 导航；既有 ADR-0059 只决定云端方向，不覆盖第三方组件依赖、执行隔离和编辑权威映射，因此新增记录而不改写历史 ADR。具体版本、源码、许可及全量实施验收只维护于 [DOC-015](../plans/2026-11-11-cloud-editing-benchmark.md#doc-015hypit-模块核对与完整交付实施方案)，当前实现状态仍取 programme/current。

## Context

用户要求自动剪辑对标 Hypit/ChatCut，一次完成完整目标，全部新增效果同时接入精修轨道与分段独立批注。AVE 已有 Host、Timeline、Command/Commit、曲线、字幕、音频、版本、Job、双目标渲染与批注框架。Hypit 已发布可复用的字幕/文字/图形组件、Composition、HTML 编译和浏览器绘帧包，无需重新开发同类引擎。

现有缺口是结构化动态图形执行、AI 修订保留高级语义、带动画的精修窗口处理、批注对象级锚点及逐条落实；只输出扁平 MP4 或在另一个编辑器中编辑无法满足目标。

## Considered Options

1. 重建时间线、曲线与图形引擎：重复现有 AVE 或成熟依赖，拒绝作为默认路线。
2. 嵌入 Hypit Studio 并双写 SVML 与 AVE：引入第二项目权威，精修、版本和批注难以保持同一事实，拒绝。
3. 仅导入 Hypit 完整成片：丢失元素与参数编辑，拒绝作为主要交付。
4. AVE 保持唯一工程权威，复用独立 Hypit 组件和执行模块，新增必要边界适配：推荐。

## Proposed Decision

- Host 仍是唯一项目与 SQLite 写入权威；组件定义、参数、元素 ID、源依赖、动画窗口和锚定关系通过现有合同及原子版本保存。Renderer 只能提交白名单对象编辑，不能持有执行代码或第三方模型密钥。
- Core 使用 AVE 类型和 RationalTime，不依赖 Hypit runtime。Hypit Timeline/Composition 是从当前 AVE 语义派生的执行输入，不是可独立编辑的项目状态。若内部采用 SVML，它也是可重建派生物，不能双向自由写入。
- 复用 `caption-fine`、`text-fine`、经核对图形组件、`film/composition/html-program` 与 `provider-html-local`。拟由 Worker 管理 Node 图形适配子进程，将现有 Job/cancel/progress/resource identity 映射到 provider 的资源与回调接口；不让新 SDK 直接启动于 UI 或获得数据库权限。
- 已有变换、转场、字幕、色彩和音频继续使用 AVE 实现；仅缺失能力进入图形适配。Caption 不重复绘制，音轨不重复混合，不引入 Hypit 独立结果库替换 AVE Object/Job/Render Bundle。
- 所有新增效果同时提供精修轨道/属性入口与分段独立批注目标。组件缓存与可编辑语义分离，新增批注合同携带对象/元素谱系并记录每条意见对应的实际变更；整体生成成功不代替逐条落实。
- 未涉及对象与用户手动参数在后续 AI 修改中保持不变；初稿复用现有 creation plan，修订扩展现有 planning exchange 的 typed patch，由 Host 转换为普通 Commands，不能通过删除保护或 unsupported 检查伪造接入。
- 同一 Semantic Render Manifest 派生 Preview/Master 各自的 Graph/Plan；图形实现、参数、资产/字体、时间映射、profile、浏览器与执行器版本参与身份和缓存。Worker 输出由 Host 复核并通过既有 QC/原子发布。
- 默认 H.264 输出不能用作透明图层。固定源码的 PNG 绘帧同样使用不透明背景，不能直接作透明层；须增加受控透明捕获并验证 alpha，或渲染包含明确授权背景的完整视觉子图并验证层级。保留 alpha、颜色、时序和可编辑结构是验收条件，不静默扁平化。具体接口设计见 DOC-015 的 DOC-016 接续。
- 当前源码许可证为附加条件的 Apache 文本。按实际部署/分发方式核对使用权，不把公开源码等同无条件商用，也不以服务包装规避。未授权商业采购、第三方托管或付费生成均不由本提案触发。

## Consequences and Compatibility

新增的是执行适配和现有协议扩展，非编辑器重写。独立发布包可能经打包改写 exports，源码版本与 tarball 必须分别固定；源码中的 private 标记不能作为不可复用结论。字体、浏览器和其他依赖分别记录版本与许可。

组件升级不得改变已保存作品的含义；精确版本/摘要缺失必须失败或恢复依赖，不用近似新版本替代。只读历史批注按原事件身份读取；新写协议统一到当前版本，不伪造历史元素锚点。新合同须同步 schemas、生成物、Host、Worker、Renderer、存储与测试；不能仅加 schema 就宣布能力完成。

云端只改变获准执行位置，不改变权威、授权、身份、成本和恢复边界。具体供应商/资源及费用未确定，不声明现有容器已经是远程渲染服务。

## Implementation / Validation / Rollback

实施依 DOC-015 U1–U7 整体交付，并在正式工作包登记路径与检查；当前 DOC 不推进 P4/P5。每种新增效果完成自动创建、精修、分段独立批注、未涉及内容保留、撤销、重开、双目标输出与导出；跨版本冲突、分割/复制锚点、失败重试和异常依赖都须验证。许可证适用与远端授权为对应真实操作边界，不把研究阶段变成重复用户审批。

回滚保留已提交对象与历史批注。若旧执行器不能理解新增对象，禁止删除语义后导出；恢复原依赖或保留可执行新版本，作品可显式回到此前合法版本。可清理派生缓存，不删除用户编辑对象、原素材或历史结果。Proposed 转为 Accepted 须由后续实际选型与实现记录支撑，不由本轮文档完成自动转换。
