# WO-R19 CI 与 GitHub Workflows

## 目标

把已存在的本地架构、Contracts、Worker、集成和桌面验收脚本拆成 GitHub Actions 的可执行门禁；统一仓库声明的包管理器为 pnpm，并保留本机已有脚本作为事实验证入口。

## 范围

- 创建 `ci.yml`、`contracts.yml`、`architecture.yml`、`worker.yml`、`golden.yml`、`acceptance.yml`、`security.yml`、`release.yml`。
- 需要 Node/Python/FFmpeg 的 Workflow 使用锁定版本，并在失败时输出对应门禁证据；Worker Workflow 额外执行 Ruff 与 mypy。
- 增加根级 `packageManager` 声明和 pnpm lockfile/安装约束；不在本工作单发布或创建 Release。
- 不改变 Contracts 主版本，不绕过 `contracts:clean`，不把真实素材或生产凭据写入 CI。

## 验收

- YAML 语法与 action 引用可静态检查。
- 架构违规、生成文件漂移、协议不兼容和 Worker 协议失败会使对应 Workflow 失败。
- `pnpm run check`、`pnpm run contracts:clean`、`pnpm run worker:qc:test` 在本机继续通过；pnpm 若本机不可用，记录为环境限制，不虚报通过。
