# WP-CA-UNIFY-001 Stage 2 single-current-version authority and exit reopening

## Outcome

Reopen Stage 2 from its stale exit claim and establish one current development
format for every logical contract, execution protocol, project database and
desktop user path. Historical records remain immutable, but no runtime may
upgrade, backfill, dual-read or execute an older AVE-owned version.

## Required behavior

- Mark the Creative Assistant programme ongoing until the corrected complete
  real-media journey and final exit audit pass.
- Return `CAP-CA-EXIT-001` and `ACC-CA-EXIT-001` to tested status while active
  Stage 2 debt or a dependency work package remains.
- Add an ADR that defines current versions, stable unsupported-version errors,
  the removal of migrations and compatibility routes, and the distinction
  between protocol versions and audit/concurrency identity fields.
- Replace current documentation compatibility routes with direct canonical
  authority navigation; do not rewrite historical ADR, Work Package or Evidence
  records.
- Register the next dependency-ready implementation package without starting it
  implicitly.

## Non-goals

- No application, Contract, database, Worker or Renderer source changes. The
  documentation-governance regression may change only to reject reintroduction
  of the removed compatibility routes and require direct canonical navigation.
- No capability promotion, real-media claim, remote publication or PR merge.

## Validation

Run documentation structure, fingerprint, sync and check gates. Verify that the
generated current state reports Stage 2 as active/incomplete, that the next
implementation package alone is ready, and that every changed path is inside
this package allowance.
