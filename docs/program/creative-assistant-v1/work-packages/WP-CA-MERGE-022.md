# WP-CA-MERGE-022 Desktop Stage 2 generation and locked-target closure

## Outcome

Allow a desktop user with an approved Creative Contract and reviewed material
to drive the existing Host-owned Material Pack, knowledge evaluation,
Direction, Story and Edit Intent generation chain without external pre-seeding,
render the resulting multi-beat execution, and prevent locked, range-locked or
Contract-protected clips from being offered as feedback targets.

## Scope

- Add one exact, fail-closed desktop generation command that invokes only the
  existing Project Host Stage 2 authorities and returns the refreshed workspace.
- Show and bind every material-permission and Evidence child approval in the
  native human review; retries reuse already approved Evidence without a second
  approval claim.
- Revalidate the exact Contract head, rights policy, approval lifetime and full
  Original-location state after asynchronous media identity verification, so a
  Contract successor or newer material decision wins without stale overwrite.
- Keep generated Direction and Story choices comparable and leave every
  selection, approval and execution on the existing exact-human action path.
- Bind feedback to the execution's exact current Contract authority before any
  diagnosis or Intent write.
- Exclude locked-track, overlapping range-lock and Contract-protected clips
  from editable feedback targets and expose the exact unavailable reason in
  the same Host-owned workspace snapshot.
- Derive one deterministic execution render canvas from the authoritative
  Original geometry and use it for both pre-confirmation RenderGraph planning
  and the final render; fail closed when geometry is missing or ambiguous.
- Cover payload validation, missing-authority zero-write failure, successful
  generation and partial retry, Renderer command wiring, public Timeline lock
  commands, material-permission interleavings, exact Contract successor
  failure, and locked-target projection.
- Reconcile shared fingerprints and Evidence without promoting capability or
  acceptance status.

## Non-goals

- No schema, storage, permission-policy, model-provider or semantic Timeline
  compiler change.
- No invented approval, silent material authorization or client-owned project
  state.
- No claim of private real-media acceptance and no PR merge authorization.

## Validation

Run focused Project Host and desktop Product suites, desktop boundary,
typecheck, architecture, full repository and synthetic final gates,
docs/fingerprint checks, independent review and exact-head remote checks.
