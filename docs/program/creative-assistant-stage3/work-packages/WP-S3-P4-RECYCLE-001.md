# WP-S3-P4-RECYCLE-001 — 安全回收站与显式永久删除

本包落实 DOC-007 已记录的独立 P4 回收站 Work Order，依赖正式关闭的
`WP-S3-RELIABLE-JOURNEY-001`。当前 `project.delete` 的直接永久删除语义、旧项目身份保护和
物理清理实现均需保留为 Host 安全边界；不恢复已移除的旧 `project.trash` / `project.restore` API。

## 用户结果与数据保护

- 为 Main 用户导航索引增加持久、原子、可验证的回收状态，并提供独立回收站页面；活动作品页
  不再列出已移入回收站的项目。重新打开或同一路径身份变化必须先通过现有 Host 身份校验。
- 使用新的、明确命名的操作完成移入、逐项恢复、全部恢复和逐项/全部永久删除。删除前显示范围，
  二次确认。取消无副作用。当前打开作品移入回收站前先确认输入已由 Host 持久化并安全关闭。
- 回收仅隐藏/标记本地项目，不移动、不删改工程内容。永久删除沿用 Host 的身份、独占锁、专属
  目录、符号链接/联接、外来文件与可恢复删除意图检查。批量删除逐项保留准确结果；部分失败不能
  报告整体成功，待清理项目能重试。
- 永久清理仅移除专属项目数据/缓存；外部原片、独立导出、共享个人档案和其他作品必须保留。
  最近索引损坏、异步操作失败或进程中断都不得把项目伪装成已恢复/已删除。

## 验收与退出

在隔离临时项目验证保存输入、移入、Main 重启、逐项/全部恢复、逐项/全部永久删除、取消、外来文件、
身份替换、锁、损坏索引、中途失败重试及外部原件保留；用户工作区现存项目不作为破坏性测试数据。
运行 manifest 的 `stage3:p4-recycle:test`、`stage3:desktop:test`、`renderer:workbench:test`、
`typecheck`、`architecture`、`docs:check`。删除成功以实际目录清理与保留项核验为准，不以列表消失为准。
