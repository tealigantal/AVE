# AVE Benchmark

## Benchmark purpose

The benchmark answers whether AVE helps a creator reach a better, more trusted
result with less avoidable work. “The code runs” and “a file was generated” are
necessary technical facts, not the benchmark outcome.

## Evaluation axes

1. **Story Quality**: factual fidelity, evidence coverage, coherence, character
   continuity, emotional legibility, beat function, and creator-intent fit.
2. **Edit Quality**: shot suitability, omission control, pacing, continuity,
   captions, audio clarity/relationship, composition, and visual finish.
3. **Collaboration Efficiency**: time to first useful cut, number of avoidable
   revisions, patch locality, approval latency, and recovery cost.
4. **Trust**: explanation usefulness, evidence precision, confidence
   calibration, blocker correctness, provenance, reversibility, and consent.
5. **User Satisfaction**: creator-rated fit, control, effort, willingness to
   keep/publish, and specific rejection reasons.

## Benchmark unit

One unit pins a project/fixture version, creator intent, rights/privacy scope,
material identity, target duration/platform, capability snapshot, system/model/
policy versions, candidate and final artifact hashes, QC, decision trace, and
review record. Results without these pins are not comparable.

## Dataset structure

Segment by content type, duration, language, creator experience, material
quality, narrative complexity, sensitive content, and current capability
support. Keep synthetic engineering fixtures, licensed real-media sets, and
private opt-in user studies separate.

## Comparison protocol

Use blinded pairwise comparison where practical, plus absolute rubric scores
and task completion evidence. Compare alternatives against the same Creative
Contract and media version. Record ties, disagreements, confidence, and reasons;
do not collapse all axes into one leaderboard number.

## Regression rule

A release cannot trade factuality, rights, privacy, provenance, failure closure,
or creator control for higher engagement or aesthetic scores. A statistically
interesting gain is not a release gate until its practical size and affected
segments are understood.
