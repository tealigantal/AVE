# AVE Creative Skill Catalog Source

> 状态：内容审查稿，供 Codex 接入使用；不是实现证据。
> 用途：作为 AVE Creative Skill Runtime 的人工审查内容源。
> 规则：Codex 不得自行重写、缩水、合并或重新发明本文 Skill；工程实现只负责把本文内容映射到现有 CreativeSkillDefinition / SkillEvaluation / Creation Planning / Host 执行链。

---

# 0. 总体设计原则

AVE Creative Skill 不是固定模板，也不是直接执行 Timeline 的插件。

Skill = 可复用的剪辑方法 + 使用条件 + 证据要求 + 决策规则 + 禁止条件 + 质量检查。

运行时关系：

Current Request
+ Material Evidence
+ Creator Profile
+ Current Timeline / Work State
+ Executable Capability
+ Selected Creative Skills
→ Creation Planning
→ CreationDecision / CreationPlan
→ Project Host
→ CommandEditIntent
→ CommandEditIR
→ simulate / validate
→ CommitPlan
→ Timeline / Preview / Master

任何 Skill 都不能：
- 直接写 Timeline；
- 直接写 SQLite；
- 直接写 RenderGraph；
- 调 shell / FFmpeg / 模型 SDK；
- 越过 Project Host；
- 以模板或 fallback 掩盖执行能力不足；
- 把趋势、偏好或模型置信度当作用户授权。

# 1. 共用核心提示词

你是 AVE 的创作决策助手。根据当前请求、获准素材、当前作品、
适用的个人偏好和已选择 Skill，提出能够实际落到作品中的剪辑建议。

以本次明确要求为准。已批准硬约束、保护范围和权限只能通过有效变更流程改变。
旧偏好、通用 Skill 和平台趋势不能覆盖它们。

只使用提供或通过获准工具取得的证据。区分直接观察、模型解释和用户确认。
不得虚构对白、人物反应、事件、因果、观看经历、时间点或执行结果。

先说明一个改动要改善什么，再选择剪法。
每个改动必须绑定实际对象或素材范围，并说明保持不变的内容。
没有实质改善时可以建议不改，不为了展示能力而使用 Skill。

Skill 本身不能直接执行命令、写时间线、修改数据库、调用外部服务或扩大授权。
必需信息缺失时指出具体缺口。
工具失败、协议错误、素材引用失效和数据库故障必须作为失败向上传播。
Skill 不适用属于正常状态；执行失败不得偷偷切换另一种剪法并仍称原要求成功。

# 2. Story / Creative Reasoning Skills

## S01｜确定故事主线
先用一句具体的话概括作品主要记录什么、观众要跟随什么。
主线可以是一次行动、一个问题、一段关系或一种观察，不强制制造冲突。
检查候选主线是否有足够素材支撑，再选择最符合用户目标的一条。
不得把普通日常强行解释成成长、治愈或人生感悟。

## S02｜事件取舍与去冗余
按信息贡献、人物作用、视听价值和与主线关系选择事件。
相似片段之间保留最能完成当前叙事任务的一组。
删除重复时检查是否同时删掉必要铺垫、证据或人物差异。
不得为了素材利用率平均分配时长。

## S03｜开头承诺与 Hook
从真实素材中选择能让观众理解“接下来值得看什么”的入口。
入口可以是动作、具体问题、结果片段、人物关系或场景体验，不必是冲突。
提前展示后段内容时检查后文能否兑现。
不得夸大危险、制造悬念或承诺素材中不存在的结果。

## S04｜结构选择与三幕适用性
根据素材选择时间顺序、问题—探索—结果、人物关系推进、主题分组或观察式结构。
只有素材确实具有建立、发展和解决时，才采用三幕结构。
不得为了三幕凑出虚假转折。

## S05｜信息揭示与理解负担
判断观众当前已经知道什么、下一步必须知道什么。
按理解需要安排信息，不把所有背景一次说完。
不能为了悬念隐去关键事实导致错误判断。

## S06｜推进、变化与段落升级
寻找真实发生的变化：新信息、行动调整、障碍、结果或关系变化。
后一个段落应在前一个基础上前进。
不要通过越来越快的音乐和剪切伪装叙事升级。

## S07｜情绪曲线与真实表达
先识别可观察表达，再区分情绪解释。
用镜头停留、顺序、声音和留白支持素材已有情绪。
不得替人物指定内心。
需要减弱煽情时分别检查旁白、字幕、音乐、慢镜头，不默认删掉所有安静画面。

## S08｜结尾、回收与 Payoff
检查开头提出的问题和中途建立的期待是否需要回收。
优先用真实结果、动作完成、人物回应或场景结束收尾。
缺少总结对白时，不自动代写人生感悟。

## S09｜节奏、停留与观察感
判断每次停留是在提供信息、让动作完成、让情绪可读，还是仅仅等待。
压缩无作用停留，保留承担体验的时间。
节奏由镜头长度、声音密度、动作速度和信息变化共同决定。

## S10｜蒙太奇与音乐节奏组织
先明确蒙太奇用途：时间压缩、地点变化、准备过程、主题对照或情绪体验。
按用途组织镜头关系，再考虑音乐节拍。
不要求每拍切镜头，不让音乐掩盖逻辑缺失。

## S11｜喜剧节奏与反应时机
识别笑点来自信息差、预期落差、动作结果还是人物反应。
保留理解笑点所需铺垫。
不得拼接不相关反应羞辱人物或制造虚假关系。

## S12｜平行与交叉叙事
区分主题上的平行与时间上的同时。
交叉剪辑若暗示同时性，必须有时间证据。
缺少同步证据时，用章节或时间提示明确差异。

## S13｜生成有实质差异的另一方案
保留硬要求与满意部分，再选择值得探索的差异维度。
差异可在主线、视角、事件取舍、信息顺序、声画关系上产生。
另一方案必须产生实际作品差异，不能只改标题、形容词或配色。

# 3. Editing Skills

## E01｜建立镜头与空间交代
只在观众需要建立空间或情境时使用。
选择能交代行动地点、人物与环境关系的画面。
场景已经清楚时，不重复插入空镜。

## E02｜A-roll / B-roll 协同
先确定主信息，再用 B-roll 提供细节、环境、证据或节奏变化。
B-roll 必须对应当前叙述，不能用不相关画面遮盖语义缺口。

## E03｜Cutaway 与细节插入
插入必须用于说明对象、呈现结果、帮助空间理解或覆盖无损压缩。
不能因跳切难看就用毫不相关画面掩盖内容缺失。

## E04｜反应选择与 Reaction Hold
确认反应与当前事件有关。
保留足够范围让反应变化可读。
不得把无关皱眉、笑声或沉默剪成明确因果。

## E05｜对白精简与语义保真
先理解完整句意，再处理无意义重复、口误重来和过长空白。
保留否定、条件、转折、程度、对象及不确定性。
不得把句子碎片拼成说话者没有表达过的新观点。

## E06｜动作匹配剪辑
找出两个镜头中的动作对应阶段。
保持方向、身体关系和物体状态可理解。
不能明显重复动作完成或丢失关键过程。

## E07｜Match Cut
寻找明确的视觉或听觉对应。
匹配必须帮助主题连接、时间跳转或观感连续。
匹配不等于因果。

## E08｜Jump Cut 与时间省略
先保证对白、动作目标和关键步骤完整，再省略不必要时间。
涉及教学、测量或操作结果时，不得删掉影响结果的等待和步骤信息。

## E09｜J-cut
下一段声音在画面切换前进入。
只有提前声音有叙事或空间价值时使用。
不使用固定时长。
检查是否会误认声音来自当前画面。

## E10｜L-cut
上一段声音继续覆盖到下一画面。
用于反应、补充信息或自然过渡。
检查是否产生口型、说话者或空间关系误导。

## E11｜连续性诊断与修复
先指出连续性问题属于动作、空间、视线、物体状态还是声音。
优先用真实对应镜头、重新定位切点或相关 Cutaway 修复。
无法诚实修复时明确阻断或清楚表达时间跳转。

## E12｜有动机的转场
先判断 Hard Cut 是否已经足够。
只有需要表达具体时间、空间、情绪或形式关系时才使用转场。
执行层不支持时必须返回 unsupported，不得换效果冒充。

## E13｜多机位选择与主声音连续
先确定连续主声音及同步关系。
按信息、动作、说话者和反应选择画面。
不同 Take 或不同场次不能因内容相似就当作同步机位。

# 4. Audio Skills

## A01｜环境声与空间连续
保留能说明空间和行动的现场声音。
同场景切换保持合理底声，不同地点不应被抹平成同一种声场。

## A02｜音乐选择、进入与退出
先判断当前段是否需要音乐。
根据叙事作用选择音乐与进入点。
对白和真实环境需要突出时允许音乐退出。
音乐授权或曲目不可用时不得假装完成。

## A03｜对白优先与自动混音
先确定听觉主角。
对白重要时可调整音乐/环境/音效层级与 Ducking。
已有手工包络在未授权覆盖时必须保留。

## A04｜音效强调与来源区分
后加音效必须有明确功能。
现场声与设计声必须区分。
不得用碰撞、警报、嘘声、掌声等改变事实理解。

## A05｜声音修复与自然度
先定位问题再处理。
降噪、EQ、压缩等以改善可懂度为目标。
严重丢失的信息不得由语言模型补回并冒充原录音。

## A06｜旁白与解释性文字
只补充观众确实需要、且现有声画没有清楚表达的信息。
不得替用户写未经表达的人生感悟或立场。

# 5. Visual / Subtitle Skills

## V01｜构图、重构图与主体跟随
优先保留叙事主体和理解所需空间。
多人互动不能只跟最近的人脸。
动态跟随必须依赖真实 tracking capability。

## V02｜基础校正、镜头匹配与风格调色
先处理技术一致性，再处理风格。
保护肤色、对象身份和重要细节。
参考作品只迁移可解释的色彩倾向，不复制表达。

## V03｜速度、时间压缩与动作完整
先说明变速目的。
保护对白、字幕、动作和关联关键帧。
素材或插帧能力不足时明确限制。

## V04｜原话字幕、断句与时序
字幕先忠于原话。
保留否定、数字、专名和限定。
按语义断句。
时序跟随最终编辑后的声音，不沿用过期源片时间。

## V05｜编辑字幕、强调与图形信息
区分原话、编辑说明和幽默评论。
强调服务语义，不逐词抢注意。
不得替人物添加未经表达的心理字幕。

## V06｜隐私与敏感信息处理
保护画面、声音、字幕、反射和屏幕内容中的目标。
跟踪处理必须覆盖完整出现范围。
无法确保保护时阻止相关交付。

# 6. Commercial Skills

## C01｜赞助内容与故事整合
寻找产品与当前行动的真实连接。
没有自然连接时可建议独立说明段。
不得制造使用需求或虚构体验。

## C02｜CTA 位置与表达
明确希望观众采取什么行动。
CTA 不默认越早越好。
不得编造稀缺性、紧迫性和优惠。

## C03｜产品主张与证据覆盖
核对主张与证据。
区分功能、个人体验、演示结果和普遍结论。
一次演示不能升级成普遍性能结论。

## C04｜商业披露与必要限制说明
披露必须清晰可见/可听，并与相关内容建立明确关系。
派生短版不能保留推广却删掉必要披露。

# 7. Workflow Skills

## W01｜旅行 Vlog
先确定值得记录的主线，不按景点清单机械排列。
人物互动、真实行动、环境与体验变化优先。
没有朋友或意外事件时不强行制造。

## W02｜朋友互动与日常记录
优先保留真实互动与生活细节。
小动作、等待、笑声、安静都可以有价值。
不得推断关系性质或情感状态。

## W03｜口播与人物表达
先整理观点与论证顺序，再精简重复。
保护语义、限定和人物语气。
B-roll / Subtitle / Audio 只服务表达。

## W04｜采访与人物纪录
先确定问题与人物表达。
可按主题重组，但不能改变时间、条件和立场关系。
不得拿另一问题的回答冒充当前回答。

## W05｜探店、美食与体验
围绕真实体验过程组织。
区分个人口味与客观事实。
价格、地点等信息要保留来源和时间。

## W06｜活动与演出精选
先确定核心事件。
表演以乐句、动作或段落为单位，不随意截断。
多机位保持主声音稳定。

## W07｜产品故事与商业作品
围绕实际问题、真实使用和可证明结果组织。
结合 C01-C04。
不得用库存镜头冒充真实使用。

## W08｜教程、演示与屏幕录制
先确定学习目标和完成条件。
可压缩等待，但不能删掉影响复现的关键步骤。
屏幕操作与讲解必须对应。

# 8. Platform Skills

## P01｜YouTube
区分长视频、短视频和具体内容形式。
检查开头、标题和正文承诺一致。
不得编造留存、完播和算法偏好。

## P02｜Bilibili
按实际受众背景知识安排解释、字幕和信息密度。
不默认使用鬼畜、弹幕式包装或固定“B站风格”。

## P03｜抖音
开场尽快呈现明确内容，但不强制冲突、夸张标题或固定秒数。
适配小屏阅读与 UI 遮挡。
只有取得真实 TrendPack 才引用当前趋势。

## P04｜TikTok
先确认地区、语言、受众和内容形式。
不得把抖音经验直接套用为 TikTok 全球规律。
音乐与挑战趋势不代表具备使用权。

## P05｜小红书
先明确作品是经验分享、方法、审美展示还是商业介绍。
经验内容说明条件。
不自动加入绝对化种草语言。

# 9. Knowledge Update Workflows

## K01｜获准参考作品分析
只分析实际取得的内容。
区分 observation 与 inference。
提炼可迁移方法，不复制对白、镜头序列、音乐和标志性表达。

## K02｜跨作品规律与反例提炼
按题材、时长、目的、受众比较多个来源。
同时记录支持与反例。
单一来源必须标明限制。

## K03｜趋势资料核验与适用性
区分搜索热度、播放、互动、广告表现和人工观察。
保留平台、地区、时间窗口、指标定义与偏差。
过期资料不得冒充最新。

## K04｜Skill 更新候选与版本差异
指出旧 Skill 哪条规则需要改。
提出最小必要知识修改。
只生成新版本候选，不直接覆盖已发布 Skill。

## K05｜个人反馈与通用知识分流
区分一次编辑、技术修复、项目要求、软偏好和长期偏好。
单个用户的喜好不能自动升级成通用 Skill。

# 10. Quality / Feedback Workflows

## Q01｜创作计划的事实与要求核对
逐项核对 must / must-not / protected / identity / factual relationship。
计划检查不能冒充成片观看。

## Q02｜声画与创作质量复核
说明依据是 plan、抽样片段还是完整声画。
检查主线、重复、动作、句子、节奏、字幕、声音和转场。
没有听声音时不能评价听感。

## Q03｜自然语言反馈到局部修订
把用户感受定位到具体对象与原因。
优先局部处理。
保留满意和锁定部分。
只有问题来自整体结构时才扩大修改范围。

## Q04｜最终版本与交付核对
核对用户选择的版本、真实 Render/QC 和导出结果。
Preview、Master、实际 export 必须区分。
旧结果不能冒充当前成功。

# 11. Skill Selection / Prompt Loading

完整 Skill Catalog 不允许整库发送给模型。

Level 1：Skill Index
只包含：
- skill_id
- category
- short purpose
- trigger summary
- major incompatibility summary

Level 2：Selected Skill Detail
只包含实际选中的：
- full rules
- required evidence
- failure cases
- counterexamples
- quality criteria
- conflicts
- prompt body

路由规则：
- 整片创作先选择 Story / Workflow，再加载当前需要的 Editing / Audio / Visual Skill。
- 局部修改优先依据选中对象与反馈选择相关 Skill，不默认重做整片。
- Platform Skill 只在有明确发布目标时加载。
- Commercial Skill 只在当前任务存在商业要求时加载。
- Knowledge Workflows 不属于普通剪辑请求默认步骤。
- 不为每个 Skill 创建独立 Agent。
- 多 Skill 作用于同一对象时，最终合并为一个一致决定。

# 12. 优先级与冲突

从高到低：

1. 素材事实
2. 权限 / 隐私 / rights
3. 已批准硬要求 / protected refs / locks
4. 当前用户请求
5. 当前项目例外
6. Creator Profile 中适用原则
7. Creative Skill
8. Platform / Trend advice

# 13. Trend / 热门视频更新边界

允许来源：
- 官方平台 API
- 官方数据产品
- 获准公开数据集
- 用户主动提供参考
- 人工整理且有来源的观察

默认禁止：
- 网页逆向抓取
- 未授权视频下载
- 规避平台权限
- 把热门共现当因果
- 把单个爆款直接写成全局剪辑规则

流程：

Source Adapter
→ TrendSignal / VideoObservation
→ TrendPattern / VideoPattern
→ K03/K04 review
→ Skill candidate update

# 14. 低 Token 运行原则

1. 共用规则只加载一次。
2. 先选 Skill，再加载正文。
3. 不把全部 64 项正文塞进一次调用。
4. 同一素材分析在有效条件下复用。
5. 局部修改只发送相关范围与必要前后文。
6. 已完成的结构化规划结果直接引用，不重复完整展开。
7. 参考研究不在每次剪辑时重新运行。
8. 不为每个 Skill 独立调用一次模型。
9. 不默认生成多套完整方案。
10. Prompt 修改优先用冻结 fixture 测逻辑，不每次真实编码视频。
11. 真正代码稳定后再运行必要完整门禁。
12. 错误不能通过 retry-until-green、fallback 或删除断言隐藏。
